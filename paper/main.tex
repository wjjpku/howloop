\begin{abstract}
Looped Transformers provide a natural architecture for implicit reasoning by repeatedly using the same set of Transformer layers.
It allows additional latent computation without adding a new set of layers for each loop.
As the hidden state evolves from one loop to the next, the same weights operate on different states, so parameter sharing alone does not determine the task-level computation performed at each loop.
This leaves open how the shared layers are reused across loops and what determines the computation they perform at each loop.

We first show that repeated use of the same layers need not imply fixed task progress.
We then demonstrate that affine steering of the entering hidden state can redirect the next frozen loop toward different targets.
We further trace this control to attention routing: patching steered attention patterns into an unsteered run recovers much of the steering effect.
Finally, we characterize how steering depends on execution depth, backbone supervision, and controller capacity.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Recent work on \emph{latent reasoning} studies how models can perform multi-step reasoning within their hidden states, without generating every intermediate step as text \citep{saunshi2025looped,geiping2025scaling}.
Recurrent architectures provide a natural way to realize this idea.
Instead of stacking a new set of layers for each additional computation step, recurrent models repeatedly apply the same transformation to an evolving hidden state \citep{dehghani2019universal}.
When the repeated module consists of Transformer layers, the resulting architecture is commonly referred to as a Looped Transformer \citep{yang2024learning,fan2025looped}.
Recent results suggest that recurrent depth is useful for multi-step computation.
Looped Transformers can learn iterative learning algorithms efficiently \citep{yang2024learning}, and recurrent depth can provide additional effective depth for reasoning \citep{saunshi2025looped}.
Adaptive looping can also substantially improve length generalization on tasks with iterative solutions \citep{fan2025looped}.
At language-model scale, Huginn and Ouro further use recurrent depth for latent test-time computation and adaptive compute allocation \citep{geiping2025scaling,zhu2025ouro}.
Together, these results suggest that repeatedly applying the same parameters can provide a useful way to extend internal computation.

A natural interpretation is to view a Looped Transformer as an iterative algorithm: the shared weights provide reusable computation, and successive loops repeatedly advance the current state.
Constructed models show that this picture can be realized explicitly, as fixed-weight Looped Transformers can be programmed to execute complex multi-step programs \citep{giannou2023loops}.
However, a model that \emph{can} be programmed this way need not organize its computation in the same way after end-to-end training.
Recent mechanistic studies point to richer learned dynamics.
Individual layers can approach distinct fixed points, while the recurrent block forms cyclic latent trajectories and repeats stages of inference across iterations \citep{blayney2026mechanistic}.
Probing studies also find that intermediate recurrent states do not always form a simple, directly readable latent chain of thought \citep{lu2025probing}.
At the same time, other work treats recurrent depth itself as something to control.
Adaptive looping, learned depth allocation, and stability-oriented training have all been used to improve behavior across different execution depths \citep{fan2025looped,geiping2025scaling,zhu2025ouro,yang2026stabilizing}.
These studies tell us what recurrent models can compute, how their trajectories evolve, and how much recurrent computation to use.
They leave a more basic question unresolved:
\emph{when the same Transformer layers are applied again, what task-level computation does that loop perform, and what determines it?}
Weight sharing fixes which parameters are reused, but not the task-level role of each application.

We answer this question in three steps.

First, \textbf{we show that repeated use of the same layers does not impose a fixed relation between loop number and task progress.}
In graph traversal, different loops can advance by different amounts or remain at an already reached target, so a learned recurrent trajectory need not follow a simple ``one loop = one task step'' interpretation (Section~\ref{sec:underdetermined}).

Second, \textbf{we demonstrate that the hidden state entering a loop can change the target produced by the next application of the same frozen layers.}
Affine steering at loop boundaries redirects the next frozen loop toward different task-level targets (Section~\ref{sec:target}).

Third, \textbf{we trace an important part of this control to attention routing.}
Patching attention patterns from a steered execution into an unsteered one recovers much of the steering effect, providing causal evidence that attention routing carries the resulting target redirection (Section~\ref{sec:hypothesis}).

We further characterize how this control depends on execution depth, backbone supervision, and controller capacity (Section~\ref{sec:generalization}).

\section{Related Work}
\label{sec:related}

\paragraph{Looped Transformers.}
Looped Transformers realize latent reasoning through layer-recurrent execution, one route within the broader landscape of internal computation \citep{zhu2025survey,li2025implicit}. Research on these models addresses three main questions. \emph{Expressivity and learnability} concern what shared recurrent computation can represent and what training can recover: recurrent architectures and programmable constructions establish computational capabilities, while empirical and theoretical analyses study the learning of iterative procedures, including multi-step optimization \citep{dehghani2019universal,giannou2023loops,yang2024learning,gatmiry2024gradient}. \emph{Reasoning and generalization} concern whether recurrent depth supplies useful additional computation and supports execution beyond the training regime \citep{saunshi2025looped,fan2025looped,soulos2024recurrent}. \emph{Scalable and adaptive recurrence} treats loop depth as a test-time compute axis: large-scale recurrent language models, learned depth allocation, stability-oriented training, and fixed-point halting study how to allocate and sustain useful computation across loops \citep{geiping2025scaling,zhu2025ouro,yang2026stabilizing,movahedi2026fixed,popescu2026adaptive}. These directions establish the capabilities, learnability, and scaling properties of recurrent computation.

\paragraph{Mechanistic studies of looped computation.}
Work on trained looped models examines \emph{readouts and supervision}, \emph{trajectories and dynamics}, and \emph{cross-loop representations}. Probing and supervision studies investigate whether intermediate states expose readable reasoning steps and which recurrent variables remain unconstrained by the readout loss \citep{lu2025probing,fan2026lotus,sharma2026readout}. Trajectory analyses identify layer-wise fixed points, cyclic trajectories, repeated inference signatures, and distinct dynamical phases \citep{blayney2026mechanistic,kapl2026growing,kim2026phase}. This line also includes causal and controlled analyses: computation-frontier studies connect training budgets to per-loop progress and validate that progress through activation-patching damage cones, while adaptive-depth studies separate trajectory formation from exit selection using gates fitted to frozen trajectories \citep{zhang2026recurrence,popescu2026adaptive}. Low-rank structure in loop-indexed key/value states provides a complementary representation-level view \citep{oneill2026looped}. Our work asks whether the entering state can redirect the next task-level target of the same trained, frozen loop. Building on activation steering, affine transformations, and patching \citep{turner2023activation,singh2024surgery,wang2023ioi}, we select different next targets through state intervention and trace that redirection to attention routing.

\section{Shared Weights Support Different Readout Trajectories}
\label{sec:underdetermined}
A natural view of a looped Transformer is that each loop repeats the same task-level step. Weight sharing alone, however, does not specify how far each loop advances toward the answer. We examine this relation between loop number and task progress using graph traversal. Each input specifies a directed graph $G$, a starting node $s$, and a path length $k$. Let $f_G(v)$ denote the successor of node $v$. The model must predict $f_G^k(s)$, the node reached after $k$ graph edges. Reading out a predicted node after each loop lets us track progress along the graph.

The models reuse a two-layer Transformer block. We denote each configuration by $D_mL_n$, where $m$ is the maximum graph-traversal depth used in training and $n$ is the number of training loops. Both D8L8 and D8L6 are trained on path lengths 1--8, using eight and six loops, respectively. Only the answer at the final loop is supervised. Intermediate readouts are not supervised, so training does not specify which node the model should predict at each earlier loop.

At evaluation time, we keep the trained parameters fixed and repeatedly apply the same shared block for 16 loops, beyond the eight or six loops used in training. This lets us observe whether the model keeps predicting the target or moves past it after the final supervised loop. We request the eight-hop target and read out predictions at loops 0--16. Loop 0 is the state before the first application of $F$. Each model is evaluated on 512 held-out ten-node cycles with all ten starting nodes, giving 5,120 examples. Figure~\ref{fig:trajectory} shows four examples from twelve D8L8 and five D8L6 runs. Rows correspond to loops, and columns correspond to nodes along the path. Each row shows how often the model predicts each node.

Before reaching the target, the readouts advance at different rates. In Figure~\ref{fig:trajectory-a}, the most frequent prediction advances one node per loop. In Figure~\ref{fig:trajectory-b}, it first stays at the starting node and then advances mainly two nodes at a time. The two D8L6 models both reach the target in six loops, but follow different intermediate readout trajectories (Figures~\ref{fig:trajectory-c} and~\ref{fig:trajectory-d}). Thus, even models trained with the same loop budget need not predict the same intermediate nodes.

After the final supervised loop, the readouts also differ. Some models continue to predict the target, while others predict nodes beyond it. Repeating the shared block therefore does not necessarily advance the decoded answer: it can also preserve an answer already reached.

These results show that shared weights and final-answer supervision do not impose a fixed relation between loop number and graph hops. The readouts identify the predicted node at each loop, rather than the hidden operations that produce it. We next test whether the entering hidden state can control the next target of a frozen loop. The target-selection and main graph mechanism experiments use the same D8L6 backbone.

\section{Steering the Next Target of a Frozen Loop}
\label{sec:target}
Section~\ref{sec:underdetermined} shows that shared weights can produce different readout trajectories. We now test whether changing the entering hidden state can control the next target of a trained loop. We learn affine maps $J$ for different targets and apply them to the same starting state. The network weights and loop budget remain fixed.

\subsection{State steering at the loop boundary}
A loop applies a shared block of Transformer layers to the current hidden states. Each layer has its own attention and feed-forward parameters; some architectures use a mixture-of-experts module in place of the feed-forward network. The entire block is reused across loops. Let $F$ denote this block and $h_t$ the sequence of token hidden states after loop $t$. The recurrence is
\begin{equation}
 h_{t+1}=F(h_t), \qquad t=1,2,\ldots.
\end{equation}

We insert a learned linear map, with an optional bias, before the next application of the shared block. The same map acts independently on every token's hidden state. It changes the states entering the block without mixing information across tokens. We call this map $J$ and the frozen network the backbone. During steering training, we update only $J$. The backbone then processes the transformed states to produce the next output.

\subsection{The same state can lead to different next targets}
Figures~\ref{fig:trajectory-c} and~\ref{fig:trajectory-d} show that D8L6 readouts can advance by one or two graph hops in a single loop. This suggests that the shared block has learned computation that can advance multiple steps along the graph. We now test whether $J$ can control this computation so that the next frozen loop advances by one or two hops as requested.

We freeze the D8L6 backbone and train two linear maps with bias. Each map uses a diagonal term plus a rank-48 low-rank term. Both maps act on the same hidden state. We use $u=f_G^8(s)$ as the start node for continuation. We train $J_{\mathrm{one}}$ so that the next frozen loop predicts $f_G(u)$, one hop beyond $u$. We train $J_{\mathrm{two}}$ so that it predicts $f_G^2(u)$, two hops beyond $u$. Appendix~\ref{app:target-setup} gives the detailed configuration.

\section{Attention Routing as a Mechanism of Steering}
\label{sec:hypothesis}\label{sec:large}
Section~\ref{sec:target} shows that we can control the next target of a frozen loop. We now study the mechanism behind this control. In graph traversal and Ouro letter-walk, attention routing carries much of the effect by changing where the network reads.

For graph traversal, we reuse the frozen D8L6 backbone and one-hop maps from Section~\ref{sec:target}. We also use Ouro-2.6B fine-tuned on letter-walk. Each input describes who passes a letter to whom. The model predicts the recipient after a requested number of transfers, expressing graph traversal in language. We freeze the fine-tuned model and train a dense affine $J$ before loops 2--4. Appendices~\ref{app:n10-mechanism} and~\ref{app:parallel} describe the models, head selection, and evaluation protocols.

\centering
\includegraphics[width=\linewidth]{figures/fig4_attention_mechanism.pdf}
\caption{(a) Attention schematic. (b--d) Attention-intervention results in D8L6 and Ouro.}
\label{fig:parallel-mechanism}\label{fig:causal}\label{fig:restore}\label{fig:routing-swap}
\end{figure}

\subsection{Restoring head outputs repairs disrupted answers}
\label{sec:restore}
We first establish that selected attention heads provide information used downstream to produce the answer. We disrupt attention by replacing queries with queries from a different starting node. The receiving run keeps its own keys and values. We then restore the selected heads' outputs from the clean run. For an intervened head, let $Q_{\mathrm{alt}}$ denote the replacement queries and $d_k$ the query/key dimension. The disruption and restoration are
\begin{equation}
 z_{\mathrm{broken}}
 =\operatorname{softmax}\!\left(\frac{Q_{\mathrm{alt}}K_{\mathrm{clean}}^\top}{\sqrt{d_k}}\right)V_{\mathrm{clean}},
 \qquad
 z_{\mathrm{restored}}\leftarrow z_{\mathrm{clean}},
\end{equation}
where softmax is taken over the visible key positions. Restoration replaces the outputs of the selected heads. If these outputs provide information needed downstream, restoring them should recover the answer despite the disrupted queries. We also restore comparison heads as a control. We score recovery on answers that were correct before query replacement and became incorrect afterward.

Restoring the selected outputs recovers answers in both models (Figure~\ref{fig:parallel-mechanism}b). In D8L6, it repairs 60.1\% of disrupted answers, compared with 0.9\% for the control. In Ouro, it repairs 62 of 63 answers, while the matched control repairs one. Restoring all affected outputs recovers every disrupted answer in both models. These results show that the selected head outputs provide information used by the subsequent computation.

\subsection{Routing and retrieved content select different answers}
\label{sec:causal}
The restoration results link head outputs to answer formation. We next separate where attention reads from what it retrieves. The receiving run uses a raw graph. The source run uses a modified graph and a different starting query. Token positions align across the two inputs, but the content at a position read by the source differs. Suppose this position contains D in the source input and C in the receiving input. A source-pattern patch should read C from the receiving values. A source-output patch instead supplies the retrieved source content and should favor D. We make C, D, and the original receiving answer distinct so that the patches predict different answers. Ouro uses paired letter-walk descriptions constructed in the same way. Let $\alpha$ denote the attention pattern, $V$ the value vectors, and $z=\alpha V$ the head output (Figure~\ref{fig:parallel-mechanism}a). The interventions are
\begin{equation}
 z_{\mathrm{pattern\ patch}}=\alpha_{\mathrm{source}}V_{\mathrm{receiver}},
 \qquad
 z_{\mathrm{output\ patch}}=z_{\mathrm{source}}.
\end{equation}

The results follow these predictions (Figure~\ref{fig:parallel-mechanism}c). Pattern patches select the answer reached by following the source route on the receiving graph in 79.8\% of D8L6 cases and 71.9\% of Ouro cases. Output patches select the source answer in 83.2\% and 95.3\% of cases, respectively. The two interventions therefore have distinct effects. The pattern specifies where to read, while the head output supplies what was retrieved. Attention routing can redirect the answer while using the receiving input's content.

\subsection{Steered patterns transfer the effect of the controller}
\label{sec:routing}\label{sec:qkv}
Routing can redirect the answer using the receiving input's content. We now test whether it also carries the effect of $J$. We run the same input with and without steering, then exchange attention patterns between the runs. Each receiving run keeps its own values. If routing carries the steering effect, steered patterns should improve the unsteered run's accuracy. The reverse exchange should reduce the steered run's accuracy. In both models, we exchange patterns at selected attention heads. Writing $J$ and $0$ for the steered and unsteered runs, the patched outputs are
\begin{equation}
 z_{J\rightarrow 0}=\alpha_J V_0,
 \qquad
 z_{0\rightarrow J}=\alpha_0 V_J.
\end{equation}
The arrow runs from the pattern source to the receiving run. Each receiving run supplies its own values and continues its own computation.

Both predictions hold (Figure~\ref{fig:parallel-mechanism}d). In D8L6, steered patterns raise unsteered accuracy from 49.0\% to 87.6\%. Full steering reaches 99.4\%. Pattern transfer recovers 76.5\% of the steering gain, averaged across the two map fits. The reverse exchange reduces steered accuracy to 76.0\%. In Ouro, steered patterns raise accuracy from 0/64 to 61/64, close to 62/64 with full steering. The reverse exchange returns accuracy to 0/64. Thus, attention patterns transfer the controller's effect even when the receiving run does not apply $J$.

The graph and Ouro experiments establish attention routing as a mechanism of steering. Restoring selected head outputs recovers information used downstream. Pattern and output patches select different answers. Steered patterns also transfer a substantial part of the controller's gain. Together, these results show that steering redirects the next target by changing where the frozen network reads. Appendix~\ref{app:mechanism-scope} reports additional results.

\section{What Limits Steering Control?}
\label{sec:generalization}
Controlling one loop does not ensure control over a longer computation. The same map must also work on states produced by earlier interventions. Its effect depends on the computation learned by the backbone and the transformations the map can express. We study these dependencies through execution length, backbone supervision, and map capacity.

\subsection{Execution length: contrasting generalization in parity and graph traversal}
\label{sec:depth-boundary}\label{sec:parity}
We consider parity as a new task. Given a binary sequence of length $n$, the model predicts whether the number of ones is even or odd: $y=(\sum_{i=1}^{n}x_i)\bmod 2$. We adapt the setup of \citet{fan2025looped} and request the answer after $t=n$ loops. The backbone is trained on lengths 1--20. We then freeze it and fit a shared affine $J$ on lengths 20--40. Appendix~\ref{app:parity} gives the detailed configuration.

Parity and graph traversal show different depth generalization (Figure~\ref{fig:boundary}). The displayed parity backbone is trained only through length 20. Fitting $J$ through length 40 maintains high accuracy at lengths approaching 200. For graph traversal, we fit a shared $J$ to maintain one-hop progress through loop 16. Accuracy declines substantially before loop 20, although steering remains active. This decline occurs across twelve D8L8 backbones, which are distinct from the D8L6 mechanism models. Appendix~\ref{sec:boundary} gives their configuration and per-seed results. Thus, steering extends accurate execution far beyond training in parity but provides little depth generalization in this graph task.

We examine readout timing to explain the stronger generalization in parity. Training pairs input length $n$ with readout loop $t=n$, so the desired slope is one. The unsteered model learns a slightly different slope under short-sequence supervision. Its accurate readouts therefore move farther from the requested loop as input length grows. An intuitive role of $J$ is to correct this slope. Fitting the map on lengths 20--40 improves the alignment and extends accurate execution beyond that range.

Figures~\ref{fig:parity}a,b show this timing change for seed 2. Near length 60, the unsteered accuracy band is roughly half a loop earlier than the requested schedule. With $J$, the band stays closer to the diagonal. The best nearby integer-loop readout is then $t=n$ rather than $t=n-1$.

We measure the timing error as $\Delta(n)=t_{\mathrm{read}}(n)-n$. Here $t_{\mathrm{read}}$ estimates the position of the recurring accuracy band (Figure~\ref{fig:parity}c). The fitted slope changes from 0.9904 without $J$ to 0.9982 with $J$, closer to one. Accumulated drift falls from 0.96 to 0.18 loops per 100 input tokens. This correction explains how a small extension of map training can support a much larger extension of accurate execution: $J$ reduces an error that accumulates with length. Appendix~\ref{app:parity} describes the estimator and reports results for the other backbones.

\subsection{Backbone supervision shapes what steering can elicit}
\label{sec:supervision-boundary}
We use Ouro antonym cancellation to study how backbone supervision affects steering. Starting from a word sequence, the task repeatedly deletes the leftmost adjacent antonym pair and joins the remaining words. Each deletion can make another pair adjacent. The model must name the pair removed at the requested deletion depth. Appendix~\ref{app:supervision} gives the training and evaluation settings.

Our earlier experiments suggest that the entering state selects how the shared loop's mechanisms are used. The map $J$ controls this selection. This account predicts that steering depends on the computation available in the backbone. If a loop lacks a reusable computation for faster progress, changing its entering state should not produce that progress. We test this prediction with two supervision strategies. Stepwise supervision trains loop $t$ to report deletion $t$, for $t=1,\ldots,4$. Final-only supervision trains the model to answer a requested deletion depth from 1--4 at loop 4. It leaves earlier readouts unconstrained.

\begin{figure}[!htbp]
\centering
\includegraphics[width=\linewidth]{figures/fig7_supervision_capacity.pdf}
\caption{(a,b) Native Ouro readout accuracy under stepwise and final-only supervision. (c) Steering deeper deletions with four loops. (d) Steering-map capacity on knowledge-graph composition. Values are accuracies (\%).}
\label{fig:ouro-native-readouts}\label{fig:steering-boundaries}
\end{figure}

The two backbones produce different readout trajectories (Figure~\ref{fig:ouro-native-readouts}a,b). Stepwise supervision produces a diagonal pattern. Each loop reports its corresponding deletion, with no accurate readout of later deletions. Final-only supervision produces earlier answers. By loop 3, it reports the correct pair in 255 of 256 cases across depths 1--4, including 63 of 64 requests for deletion 4. The final-only backbone therefore reaches the requested answer in fewer loops. The stepwise backbone follows the prescribed one-deletion-per-loop readout schedule.

We freeze both backbones and train one shared rank-128 residual affine map for each. Each map receives 500 updates on deletion depths 1--8. Every request uses exactly four network loops. This tests whether the same map family can produce deeper task progress from the two frozen backbones. Depths 5--8 are outside backbone training but are included when fitting $J$.

The steering results match the difference in native readouts (Figure~\ref{fig:steering-boundaries}c). On the same held-out sequences at depths 5--8, the final-only backbone answers 251/256 requests correctly with $J$ (98.0\%). The stepwise backbone answers 20/256 correctly (7.8\%). Both score zero without $J$. The affine map produces deeper cancellation with the final-only backbone. The same map family and training budget do not achieve comparable control with the stepwise backbone.

The native readouts and steering results support our account of state control: what $J$ can elicit depends on the computation available in $F$. An affine map changes the state supplied to that computation. It does not ensure that a backbone trained for one prescribed progression can perform several deletions within the same loop budget. Backbone supervision therefore shapes both the native progression and the deeper computation accessible through steering.

\subsection{Beyond affine steering: map capacity extends the range of control}
\label{sec:complexity-boundary}
State steering need not use an affine map. A multilayer perceptron (MLP) can transform token states nonlinearly, and an attention module can also combine information across token positions. We test whether these more expressive maps sustain control where affine steering fails. The task is synthetic knowledge-graph composition. Each input specifies a starting entity and a sequence of relations, and the model predicts the final entity. Longer compositions require more relational steps.

We keep the trained backbone and knowledge-graph world fixed. We compare four forms of $J$: rank-48 residual affine, dense affine, residual MLP, and causal attention. Each map is shared across loops and trained with the same curriculum through composition length 32. Figure~\ref{fig:steering-boundaries}d reports accuracy on fresh compositions at these trained lengths. Appendix~\ref{app:cross-task} gives the architectures and experimental settings.

More expressive maps extend the range of successful steering. At length 24, rank-48 affine steering reaches 0.78\% accuracy, and dense affine reaches 32.81\%. The MLP reaches 75.00\%, and attention reaches 84.38\%. Thus, nonlinear and token-mixing maps solve longer compositions with the same frozen backbone. At length 32, however, all four maps lose accuracy. Greater map capacity extends the useful range but does not ensure sustained control.

These results show why successful affine steering is not automatic. A single shared $J$ does not sustain accurate computation on every task, even when longer compositions are included in training. When a simple affine map provides sustained control, it shows that the backbone's computation is accessible through that form of state intervention. More expressive maps can make additional computation accessible. Neither their capacity nor their repeated use guarantees reliable long-horizon execution.

\section{Discussion and Limitations}
\label{sec:limitations}
The experiments connect three levels of description. Native trajectories show that weight sharing leaves room for different relations between loops and task progress. State steering then selects different next targets with the same frozen computation. In D8L6 and Ouro, activation patching traces much of this control to attention routing: changing where the model reads can change its answer without replacing the receiving input's content. This gives the schematic in Figure~\ref{fig:mechanism} a concrete experimental interpretation.

Reliable extended execution imposes further requirements. The controller must remain effective on the states reached after its earlier interventions, the backbone must supply suitable computation, and the map must be expressive enough to direct it. The length, training-strategy, and capacity comparisons expose these dependencies separately. They motivate evaluating both target selection at a controlled state and the behavior of the resulting recurrent trajectory.

The eight-node continuation sample and historical Ouro checkpoint also lack verified graph exclusions from training; the appendices distinguish those evaluations from training-excluded cohorts.

Several cross-task comparisons use one backbone and one map per condition, and the map-capacity comparison changes several properties at once. The Ouro training comparison changes both supervision and request format. These results establish differences between the tested systems, while replicated and more targeted comparisons would determine which individual design choices account for those differences. The principal distinction remains: steering a frozen loop toward a desired target is achievable, but reliable long-horizon execution must be demonstrated separately.

\section{Ouro Antonym Cancellation under Two Training Strategies}

\paragraph{Backbone supervision and request format.}

Stepwise training supplies a prompt requesting four deletions and supervises the pair removed at deletion $t$ after loop $t$, for $t=1,\ldots,4$. The comparison therefore contrasts learning to answer a requested depth at the final loop with learning a prescribed progression of intermediate answers.

\section{Controller Families for Knowledge-Graph Composition}
\label{app:cross-task}
The synthetic world contains 128 entities and 16 relations. A task specifies a starting entity and a relation sequence, with the final entity as the answer. The frozen input-once network uses two blocks, width 256, eight heads, and no positional encodings. All controller families are evaluated on this same world and backbone.

We compare identity-plus-rank-48 affine maps, $J(h)=h(I+AB)+b$, dense affine maps, residual MLPs of width 256, and causal attention maps. For a composition of length $m$, execution begins with one $F$ and continues with $m-1$ repetitions of $J$ followed by $F$. The curriculum increases maximum supervised length through 4, 8, 12, 16, 20, 24, 28, and 32, allowing up to 5,000 updates per stage. Training uses truncated unrolling with an answer position that advances along the composition.

Each evaluation cell contains 128 fresh compositions in the same world. All displayed lengths belong to the completed curriculum, so Figure~\ref{fig:steering-boundaries}d tests new compositions at trained lengths.

There is one fit per family. Parameter count, nonlinear transformation, and token mixing vary together across these families. The comparison establishes the importance of map choice for this backbone; it neither isolates one capacity feature nor ranks the families across seeds, worlds, or unseen lengths.
