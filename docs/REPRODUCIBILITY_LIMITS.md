# Reproducibility limits

This repository supplies the pinned arXiv v1 paper source, experiment source, saved example-level outputs where available, and scripts to recalculate paper figures and statistics. It excludes large model weights. A successful CPU audit confirms the saved evidence and its aggregation, not that training was rerun or every GPU forward pass repeated independently.

The earlier eight-step composition set uses one D8L6 backbone (seed 6) and two controller fits. arXiv v1's Figure 8 instead uses an independent 512-graph set and plots seed 6; saved predictions for five backbones and two controller fits per backbone are included under `experiments/revision/arxiv_v1_composition/`. The CPU audit verifies saved predictions, sample selection, old/new graph disjointness, and the 3,000 graph-bootstrap summary. The original-weight inference run is not repeated here. The selected Graph mechanism adds separate backbones (seeds 10 and 13); controller fits within a backbone are not independent backbone replications. The matched-supervision comparison uses five paired final-only/stepwise runs with paired initialization and token-stream hashes; saved lock and prediction evidence is checked by `audit_paper_matched.py`. The Ouro 256-pair analyses are distinct from the earlier letter-walk records.

Runtime source uses neutral placeholder paths and is copied to an isolated work directory by `prepare_runtime.py`. The latest selected-seed and matched campaigns depend on original checkpoints and full training infrastructure absent from this repository. Floating-point and hardware differences can change boundary predictions. The paper's artwork and locally generated plot PDFs are not promised to have byte-identical PDF encodings.

Appendix H Qwen and KG numerical claims are backed by prompt/query-level archived predictions and original-weight source snapshots. The archive omits the large Qwen base model, the adapted Qwen checkpoints, and KG checkpoints. `provenance/additional_controls.json` records their hashes. The Qwen CPU audit uses exact complete-answer matching after trim and casefold, matching the manuscript; it does not treat parsed partial answers as correct. The KG CPU audit uses the same 1,024 queries per length for raw and controlled predictions. Public source paths were adapted, so their hashes differ from the recorded original hashes. These CPU checks do not establish a fresh independent GPU replay.
